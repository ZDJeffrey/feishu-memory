# Wiki 分层入口

Wiki 为用户和 Agent 共用入口。知识库根目录下，首页「知识与协作入口」保存协作规则与导航；每个项目和学习主题是一棵同级目录树，树根为短概述，详细资料作为子页面维护。

## 建立或连接

1. 优先复用本机配置中的 Wiki。无配置时按 setup.md 的稳定标题定位入口，用 wiki +node-get 解析 space_id、node_token、obj_token 和实际 parent_node_token；创建响应可能包含虚拟根，以回读结果为准。
2. 首次建立独立知识空间与首页，核对 visibility=private、open_sharing=closed 和成员范围。页面沿用飞书默认分享设置（组织内获得链接可阅读、关闭对外访问），不逐页修改；分享范围、协作者与权限的变更由用户提出。
3. 初始页面为首页、核心摘要、Agent 记忆、项目、学习与研究；Agent 记忆下按需建立个人偏好档案（协作规则唯一正文）、写作规范、思考与判断、通用术语表与读写协议，核心摘要只提炼要点并链接这些正文。每个项目和学习主题在知识库根目录建立一棵与首页同级的目录树，树根为概述，子页面按骨架组织：设计、决策记录、实验、术语表与相关工作；表格、多维表格、幻灯片与 PDF 也作为子节点。页面标题不加项目前缀，由目录表达归属。云盘中的已有资料按用户授权用 `wiki +move` 移入（文件夹不能整体移动，需逐个移动文档；token 不变，原位置留下快捷方式）。
4. 本机配置只记录 profile、wiki.space_id、首页节点与核心摘要入口，见配置模板。首页列出根目录下的各目录树；其余页面通过链接与 wiki +node-list 逐层定位。
5. 建立或调整后读取核心摘要与首页、一个概述、一次限定空间搜索和一次章节读取，确认入口与预算。

逐层列出节点时每次只看当前层的少量结果，不自动递归读取。快捷方式先解析原始目标，再判断是否在记忆空间内。标题不带项目前缀，搜索结果需用 wiki +node-get 查看父节点确认所属项目。

## 页面内容

| 页面 | 内容与维护 |
| --- | --- |
| 核心摘要 | 常用协作与风格规则，细则通过链接按需读取；用户规则变化时与详细准则同步。 |
| 首页 | Agent 记忆入口与根目录下各目录树的一句话用途；不汇总项目进展。 |
| 分类索引 | 简短资源名、用途与链接，按实际条目扩展。 |
| 项目或主题概述 | 范围、当前状态或关键认识、相关资料入口、读写范围与必要日期。 |
| 详细资料 | 完整论证、实验、记录、报告和源文件；原位置作为正文依据。 |

启动正文约 4000 字符，包含返回的 XML。每个概述应短到能够与核心摘要一起完整读取；超出时先读目录并缩小范围。常规展开单次约 12000 字符。已知项目或主题直接读取其概述，同一会话复用已读规则。

## 范围与收尾

资源登记保存入口、用途、读取范围、可写位置及授权依据。外部内容仍按 external-resources.md 执行；Wiki 链接不扩大操作范围。Base 仅在需要条目筛选、关联或统计时接入，Sheets、画板和 Slides 按内容选用。

任务结束先更新详细产物和状态，再按实际变化更新对应概述；首页仅在分类或入口变化时更新。概述保留决定后续读取所需的信息，不复制完整报告；同一结论只在一处正文维护，其他位置链接。被取代的内容直接替换或删除，详细文档不按轮次追加章节。正文与概述分别回读，出现版本冲突先重新读取合并。

Wiki 检索使用 --space-ids 限定空间；doc-types 表示底层内容类型，Wiki 中的正文通常为 docx。不要用 --doc-types wiki 筛选 Wiki 正文，本轮实测该组合会漏掉已存在的 Docx 页面。
